# PHD Stefan Paving

A CUDA solver for a three-dimensional Stefan problem involving multiple briquettes. It
models heat transfer and phase change across the briquettes and surrounding material on a
regular 3D grid.

CUDA-решатель трёхмерной задачи Стефана для системы из нескольких брикетов. Моделирует
перенос тепла и фазовые переходы в брикетах и окружающем материале на регулярной трёхмерной
сетке.

## Описание

Начальные температуры брикетов и окружающей среды различаются. В области фазового
перехода учитываются зависящие от температуры свойства материала.

Программа является исследовательским кодом с параметрами эксперимента, заданными непосредственно в исходниках. Она записывает текстовую сводку и снимки VTK, которые затем можно просматривать средствами научной визуализации.

## Разработка и проверка изменений

**Основные точки изменения:**

- `src/paving.cu` - численная модель нескольких брикетов, CUDA-ядра и вывод данных;
- `CMakeLists.txt` - сборка CUDA-программы.

**Температурные свойства:** в `src/paving.cu` CUDA-функция `c_ro(t)`
рассчитывает объёмную теплоёмкость с учётом интервала фазового перехода
и скрытой теплоты; `k(t)` задаёт температурно-зависимую теплопроводность.
Обе вызываются ядром `solve`, а границы перехода определяются
`freeze_temp_d` и `delt_d`. Изменяя модель материала, проверяйте
согласованность этих функций с формулой обновления температуры в `solve`.

**Геометрия и граничные условия:** ядро `init` заполняет начальные
температуры и выделяет включения по условию принадлежности к сфере;
несмотря на название проекта, геометрия в коде задана сферическими
областями через `sphere_count_*_d`. Ядро `solve` обновляет внутренние
узлы явной конечно-разностной схемой, используя соседние температуры
и функции `c_ro` и `k`. На границах по X применяется `bound_temp_d`,
а для Y и Z значения соседних граничных ячеек копируются изнутри.
При изменении краевых условий проверяйте порядок ветвей `if`/`else if`
и совместимость шага `dt_d` с пространственным шагом `dx_d`.

**Выходные данные:** `out.txt` содержит максимальную температуру вдоль
центральной линии по X, а не максимум по всей трёхмерной области.
`plot/result_<time>.vtk` использует номер шага расчёта, а не время в
секундах: данные записываются как `STRUCTURED_POINTS`, с полем `heat`
в виде бинарных 32-битных чисел с переставленным порядком байтов.
Если расширять циклы параметров эксперимента, учитывайте, что имена
VTK-файлов не включают номер эксперимента и могут перезаписываться.

**Ограничения изменения параметров:** массивы выделены на размеры
`max_size_x = max_size_y = max_size_z = 500`, а центральная линия сохраняется
в `centre_line[500]`. После изменения `dx`, числа сфер или размеров областей
проверяйте все вычисляемые `problem_size_*` до копирования данных с GPU.
Интервал сохранения задаётся `time % ((int)(0.1 / dt))`: для него требуется
положительный `dt`, не превышающий `0.1`; больший шаг может дать деление
по модулю на ноль. Изменение шага само по себе не проверяет устойчивость
численной схемы.

**Файлы сборки:** `CMakePresets.json` определяет профили конфигурации CMake; `CMakeLists.txt` включает CUDA и описывает цель сборки. Численные параметры модели и свойства материала задаются кодом.

**Проверка изменений:** При изменении геометрии или теплообмена проверяйте согласованность индексов трёхмерной сетки, граничных условий и параметров шага. Выполните сборку и контрольный запуск по инструкциям выше.

## Сборка

Нужны CMake, CUDA Toolkit и совместимый NVIDIA GPU.

```sh
cmake --preset release
cmake --build --preset release
```

Исполняемый файл:

```text
build/release/paving
```

## Запуск

```sh
mkdir -p plot
./build/release/paving
```

Параметров командной строки нет. Температуры, размер брикетов, количество элементов, шаг сетки и шаг времени задаются непосредственно в `src/paving.cu`.

## Результат

Основные численные результаты записываются в `out.txt`. Поля температуры периодически сохраняются в бинарных VTK-файлах:

```text
plot/result_<time>.vtk
```

## Модель

Расчет использует трехмерную явную конечно-разностную схему. В начальном условии внутри объёма размещается набор брикетов, окруженных другой средой; теплообмен и фазовый переход рассчитываются во времени на GPU.
